## PC検証(まずこれ)

`index.html?sim=1` をブラウザで開く(幅600pxに固定推奨)。GPX再生の代わりに選択ルートを時間圧縮で自動歩行する。

- 基本6入力: `←→` パネル/選択, `↑↓` 輝度(黄⇄白), `Enter` 決定/WP手動確認, `Escape` 戻る
- クリック代替: 左1/3=←, 右1/3=→, 中央=Enter, 最下部=Escape
- **sim専用キー(障害注入)**: `d` 逸脱80m注入/解除, `l` GPS喪失35秒, `a` 低精度化(判定除外の確認), `t` テレポート1発(誤警報しないこと), `p` 停止(ETA凍結), `s` 速度×5/20/60, `n` 日没95分前へ時刻ジャンプ, `g` ゴール手前へ早送り

確認フロー例: 起動→免責→ルート選択→ready→開始→`d`で逸脱→warn遷移→`Enter`で5分抑制→`d`で復帰→自動解除→`n`で日没警告色→`g`→`Escape`でサマリー。

## 実機検証の順番(Phase 0)

1. **spike.html を先に登録して1日持ち歩く。** 見るポイント:
   - fix間隔と精度(要件F2/F4の閾値の妥当性判断材料)
   - IMU種別と `alpha` / `webkitCompassHeading` の意味 — 体を北に向けて値をメモ。矢印の向きが逆・ズレる場合は index.html 内 `startOrientation()` の1行を修正
   - **消灯60秒→再点灯で「HB欠測」が出るか。** 出る=消灯中JSは停止 → 本アプリはプル型設計(再点灯瞬間に判定)なので想定内。出ない=常時監視が生きる(ボーナス)
   - Battery APIの有無(無ければ⑤帯のバッテリー表示は恒久的に断念)
   - 権限プロンプトが毎回出るか(毎回ならreadyの文言調整)
   - ログ回収: `WEBHOOK_URL` 定数に webhook.site 等のURLを貼ってからデプロイ → 電波のある場所でピンチ2回目
2. index.html を近所の低山1本。視認性・フォント・閾値だけ調整(ロジックはPCで検証済み)

## ルート差し替え

```
python3 gpx2route.py yamap_export.gpx --id kurohime --name "黒姫山 表登山道" > route.txt
```

出力を index.html 内の `var ROUTES = [` 配列に追加(1ルート2〜5KB目安)。CTはGPXにない場合、標準式(登り300m/h+4km/h)で自動生成される。実測CTを持っているなら `--ct "0:0,3200:90,5800:150"` 形式で沿道距離:累積分を渡す。**同梱デモ3本は架空ルート**なので実山行前に必ず削除を。

## 要件v0.1からの意図的変更(レビューで合意した内容)

1. **F4はプル型**: Notifications非対応が公式確定のため「グランスした瞬間に判定済み」設計。`visibilitychange`/`pageshow` で即時に現在地取得→逸脱ならwarnで復帰。消灯中もJSが生きる端末なら従来のプッシュ動作も自動で有効
2. **Service Worker追加**(単一HTML原則の唯一の例外): 圏外での再起動に必須
3. **戻る操作は History API 経由**: 公式のバックジェスチャー仕様(シェルが `history.back()`)に合わせ、select→ready→main→warn を pushState 4段で管理(上限5以内)。権限解決前に pushState しない(公式の既知ハング対策)
4. **矢印は「ルート120m先」**(逸脱時のみ復帰方向): 次WPへの直線方位は稜線・九十九折で誤誘導し得るため
5. **warn画面は黒背景+赤は帯と数値のみ**、点滅は帯だけ(§3と§6の矛盾解消、アクセント5%則準拠)
6. **逸脱マッチングに前進バイアス**: 往路復路が同一線形のピストンで折り返し後に往路へ張り付く問題への対策(テストで再現→修正済み)
7. 抑制中は⑤帯に残時間表示 / 手動でwarnを閉じた場合は60秒再警告猶予
