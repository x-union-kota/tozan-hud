## A. 地図・地形(実機確認からの修正)

### A-1. urbanドメインでは等高線を描かない【即時】
晴海の実機で、1m等高線は岸壁段差と建物基壇しか描かず、意味ありげなノイズになった(正直さゲートの逆)。
- `domain==='urban'` では地形レイヤ(DEM等高線)を**描画しない**。黒地+ルート+WPのみ
- 優先2の `route.vec`(OSM道路ベクタ)が実装され次第、urbanの既定表示をそれにする
- クレジット行は表示内容に連動: 等高線なし→クレジット省略、vecあり→「地図: © OpenStreetMap contributors」

### A-2. mountainの等高線は間隔を階層化
1m固定は山域で真っ黒になる。
- 主曲線 10m(最暗 `#33302b`) / 計曲線 50m(中 `#6b675c`) / **尾根線(最明 `#c9c4b6`)**。谷線は青系 `#2e4650`
- 尾根線: DEM勾配場の稜線抽出(局所最大の連結)。抽出が不安定ならまず計曲線+主曲線のみで出し、尾根線は次段
- ズームは表示範囲の実寸に応じて自動(上限: dem5a_png z15 → 欠損域は dem_png z14 にフォールバック)
- 高尾山で目視確認: 「どの尾根に乗っているか」が読めることが受け入れ条件

### A-3. ルート吸着 `--snap-osm` を晴海にも適用
晴海フラッグ周回も概形。皇居と同様に吸着する(仕様は DATA_SOURCES.md 優先2 参照)。
晴海のOverpass取得(ユーザー実行):
```
curl -sG https://overpass-api.de/api/interpreter --data-urlencode 'data=[out:json][timeout:60];(way["highway"](35.643,139.765,35.660,139.790);way["railway"](35.643,139.765,35.660,139.790);way["natural"="water"](35.643,139.765,35.660,139.790);relation["natural"="water"](35.643,139.765,35.660,139.790););out geom;' > harumi-osm.json
```
取得後 `test/fixtures/harumi-osm.json` に置き、皇居と同じ検証(ズレ実測→吸着後ズレ<5m)を通す。

## B. 透視・星座は頭の向きに追従する【即時・最優先バグ】

矢印キーで方向を回す仕様はNG。設計原則は **視線=クエリ**。
1. 透視/星座の表示方位は常に `S.heading`(deviceorientation alpha直 → 円形EMA → 較正ゲート)から取る。手動で方位を回す操作は全撤去
2. ←→ は地上レイヤのフィルタ切替、↑↓ は地上⇄空の切替のみ(v3.1の仕様に戻す)
3. 方位が取れないときは黙って手動に落とさず「方位較正中…/方位取得不可」を表示。手動パンは `?sim=1` のシミュレータ専用に隔離(`sim.headOff`)
4. 実機で方位が来ていない場合は HANDOFF.md §4-1(権限は同一ジェスチャー内・履歴変更前に同期発行)を疑い、診断画面の ori/abs イベント数で切り分ける
5. **仰角追従**: 空レイヤは方位に加えて `beta`(ピッチ)に追従する。表示する高度帯を「いま見上げている仰角 ±25°」にする。betaが取れないときは既定帯(仰角20〜60°)。診断画面に現在ピッチを表示

受け入れ条件: 透視画面を開いて首を左右に振ると方位目盛が流れ、上を向くと空レイヤの高度帯が上がる。キー操作なし。

## C. HUD追加機能(9本・すべて採用)

各項目: 元ネタ / 表示 / 計算 / 正直さゲート / 受け入れ条件。
**画面予算**: メイン画面に常設で増えるのは C-5(方位テープ)と C-1(引き返し行)の2つだけ。
C-2はゴースト文字の置換、C-4/C-9は矢印の周辺に統合、C-7/C-8は↓詳細ページまたは帯ローテーションに置く。
1画面に収まらなければ画面遷移で分割(ガイド原則)。

### C-1. 引き返し限界時刻 ← ダイビングコンピュータの無減圧限界
- 表示: `引き返し限界 14:10 (あと35分)` 1行。メイン画面常設。残り15分以下で `acc2`、0以下で `acc1`+帯「引き返し限界を超過」
- 計算: `limit = sunset − margin − returnCT(現在地)`。`returnCT` = 現在地から最寄りの安全終点(スタート地点 or ゴール、CTが短い方)までの標準CT(標準式: 下り 500m/h+水平4.5km/h、登り 300m/h+水平4km/h)。`margin` 既定60分、設定で30/60/90
- 毎tick再計算。日没は既存 `S.sun.sunset`
- ゲート: `S.along` 未収束・日没未取得なら非表示。urbanドメインでは非表示(住宅地では意味が薄い)
- 受け入れ: 高尾山simで、進むほど限界時刻が早まり、山頂付近で「あと○分」が最小になる。core.test に `turnaroundLimit()` の境界テスト

### C-2. デルタバー ← レーシングのゴースト差表示
- 表示: 中央基準の横バー(±60秒でフルスケール)+ `+3.2s ▲` / `−1.8s ▼`。▲=差が縮んでいる。現行「ゴースト後方 40m」文字を置換
- 計算: `delta = ghostTimeAt(along_now) − elapsed_now`(秒)。ゴーストが同じ沿道位置を通過した時刻との差。トレンドは直近30秒のdeltaの変化符号
- 3ソース(前回/1周目/標準CT)+今後の目標ペース、すべて同じ式
- ゲート: 既存のゴースト消灯条件(鮮度90秒・ルート外・未収束)をそのまま継承
- 受け入れ: simで一定ペースで走ると標準CTゴーストのdeltaが線形に変化する。core.test 追加

### C-3. エッジキュー ← F-35 HMDSのオフボアサイト表示
- 表示: 透視モードで対象が±30°の窓の外にあるとき、画面左右端に `← 富士山 72°` / `ゴースト 140° →`。各辺1件まで
- 優先順位: ロック中の対象 > `--vis` 実線の峰 > ゴースト > 最寄りの対象
- 計算: `angDiff(brg, heading)` の符号と絶対値。既存 `identItems()` の結果から窓外のものを抽出
- ゲート: 方位較正中は透視自体が出ないので追加なし
- 受け入れ: simで `headOff` を回すと、対象が窓から出た瞬間にキューへ移り、戻ると消える

### C-4. 実進行ベクトル ← 航空HUDのフライトパスベクター
- 表示: 方位矢印(ルート先)の外周に小さな三角マーカー=実際の移動方向。ルート方向と重なっていれば安心、離れ始めたら予兆
- 計算: 直近15秒のGPS位置から `bearing(oldest, newest)`。移動距離10m未満または速度0.5m/s未満は非表示
- ゲート: 精度 `acc>50m` は非表示。停止中は消える(静止時の方位ノイズを出さない)
- 受け入れ: simでルートから斜めに離脱させると、逸脱警告(50m)より前にマーカーが矢印から離れる

### C-5. 方位テープ常設 ← 航空HUDのヘディングテープ
- 表示: メイン画面上端、幅600・高さ約50px、±45°の窓、15°刻みの目盛。マーカー: 次WP(main)・ゴール(txt)・日没方位(acc2)・ゴースト(dim)・自宅(dim)。中央に現在方位の数字
- 透視モードは「このテープを±30°に拡大して対象名を乗せたもの」という位置づけに再定義(見た目の連続性)
- ゲート: `headingSettled` でなければテープ全体を「較正中」表示に。GPSなしでもテープ自体は出る(方位だけ)
- レイアウト: 既存メイン画面の上部要素を50px下げる。最小フォント18pxを維持
- 受け入れ: smokeで各マーカーの描画位置が方位差に比例していること

### C-6. 注視ロック ← HMDSのルック&ロック / メトロイドのスキャンバイザー
- 操作: 透視モードで中央±8°に入った対象をピンチ(Enter)でロック。ロック中は首を回してもラベル・距離・方位差が画面に残る(窓外ならエッジキューに昇格)。中指ピンチ(Escape)で解除、もう一度Escapeで透視を抜ける
- 表示: ロック対象は枠付き `[富士山 3776m 87km ←12°]`
- 状態: `S.identLock = {n, brg, dist}`。透視を抜けると解除
- 受け入れ: smokeで Enter→ロック→headOff変更→ラベル残存→Escape→解除

### C-7. 勾配ラダーと次の登り予告 ← ピッチラダー + Garmin ClimbPro
- 表示: 現在勾配 `↗ 9%` + `300m先 登り 400m 平均12%`。↓詳細ページに常設、メインでは帯ローテーションに1件
- 計算: 断面図から、この先で勾配8%以上が100m以上続く区間の開始距離・長さ・平均勾配。現在勾配は直近50mの標高差
- ゲート: `S.along` 未収束は非表示。urbanは非表示(勾配の意味が薄い)
- 受け入れ: 高尾山simで金比羅台の登りを正しく予告する。core.test に `nextClimb()` テスト

### C-8. 実効速度(VMG) ← 帆走のVelocity Made Good
- 表示: `実効 68m/分`(mountain)/ `実効 5:12/km`(urban)。↓詳細ページ。urbanのペース表示はこれに統一してよい
- 計算: `Δalong / Δt`、直近60秒の窓。逸脱中・後戻り中は負またはゼロになるので表示は `—`
- ゲート: 未収束・ルート外は `—`
- 受け入れ: simでルートを九十九折りに横切っても、沿道距離ベースの値が一定に近い

### C-9. コース偏差バー(CDI) ← 航空・海事の定番
- 表示: 矢印の下に小さな横バー。中央=ルート上、左右に振れ=ズレ方向。スケール±50m、**数字は出さない**
- 50m超は現行の「ルート外」フローへ切り替え(バーは消す)。既存学習「ルート外では曖昧な数字を出さない」を遵守
- 計算: `S.proj` の距離に符号を付ける(ルート進行方向ベクトルとのクロス積で左右判定)。core に `signedCrossTrack()` を追加
- 受け入れ: simで右へ20m離脱→バーが右へ、50m超→バー消灯+ルート外
