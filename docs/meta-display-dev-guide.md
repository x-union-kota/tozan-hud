## 0. 結論：守るべき5原則

1. **単一HTMLファイル・依存ゼロ**（CDN禁止）
2. **600×600固定・スクロールなし**
3. **入力は6つだけ**（←→↑↓ / Enter / Escape）に全機能をマップ
4. **背景は純黒 `#000`**（加算ディスプレイでは黒＝透明）
5. **PCブラウザで完全に動作確認できる状態を保つ**（実機検証は最後の1回に）

## 1. 画面設計

### 固定仕様

```html
<meta name="viewport" content="width=600, initial-scale=1.0, user-scalable=no">
```
```css
html,body{ background:#000; overflow:hidden; }
body{ width:600px; height:600px; position:relative; user-select:none; }
```

- **スクロール禁止**。画面外に情報を置かない。1画面に収まらないなら画面遷移で分割する
- レイアウトは `position:absolute` でゾーン固定が安全。フレックスの折り返しで意図せず縦に伸びるのを防ぐ
- 情報の優先順位を上から：**メニュー → メインビジュアル → ステータス → メッセージ**

### 配色（実機で成功した組み合わせ）

| 用途 | 値 | 備考 |
|---|---|---|
| 背景 | `#000` | 透明として抜ける。**必ず純黒** |
| メインカラー | `#ffd83b` | 高輝度の黄は視認性が非常に高い |
| テキスト | `#f5f1e6` | 純白より目に優しい |
| 非アクティブ | `#6b675c` | これ以上暗いと屋外で消える |
| アクセント | `#ff5a60` / `#f5a11c` | 使用は面積の5%以下に |

**注意点：**
- 加算ディスプレイなので**暗い色＝薄く見える**。グレーの階調で情報を区別する設計は失敗する
- 明度差で区別する。彩度差・色相差だけでの区別は避ける
- 影・グラデーション・半透明オーバーレイはほぼ見えない。**ベタ塗りと明確な枠線**で構成する

### フォント

- **最小18px、標準20〜24px**。PCで「大きすぎ」と感じるくらいが実機で適正
- 等幅フォント（`Courier New` 系）はドット感が出て、この画面と相性が良い
- ひらがな主体・短文にする。漢字の細い画数は潰れる

## 2. Neural Band 入力設計

### マッピング（OSがキーイベントに変換）

| ジェスチャー | キーイベント |
|---|---|
| 左右スワイプ | `ArrowLeft` / `ArrowRight` |
| 上下スワイプ | `ArrowUp` / `ArrowDown` |
| 人差し指ピンチ | `Enter` |
| 中指ピンチ | `Escape` |

### 実装の型

```js
window.addEventListener('keydown', function(e){
  var k = e.key;
  // スクロール等のデフォルト動作を必ず殺す
  if(['ArrowLeft','ArrowRight','ArrowUp','ArrowDown','Enter','Escape',' '].indexOf(k)>=0) e.preventDefault();

  // モードごとに分岐（重要）
  if(state.mode==='choose'){ /* ... */ return; }
  if(state.mode==='game'){ /* ... */ return; }
  // main
});
```

**設計ルール：**
- **モード（画面状態）を変数で持ち、同じキーに文脈別の意味を割り当てる**。入力が6つしかないので、これをやらないと機能が足りなくなる
- `Escape` は常に「1つ戻る」で統一。迷子になったときの脱出口を必ず用意する
- **左右＝選択移動、Enter＝決定** のカーソルUIが最も安定。直接操作より確実
- タップ用の `click` ハンドラも並行して実装しておくと、PC・スマホでの検証が一気に楽になる
- 長押し・同時押し・連打は認識が不安定なので前提にしない

## 3. アセットの扱い

- **画像は base64 で HTML に直接埋め込む**。外部ファイル参照は読み込み失敗のリスクがある
- 埋め込み前に必ず圧縮する。今回の処理：**背景透過 → 余白トリム → 高さ300pxへリサイズ → 32色に減色**（結果：1枚2〜5KB）
- HTML全体で**100KB以内**を目安に。今回は35KBで快適に動作した
- SVGはインラインで書けば軽量かつ動的に色や形を変更できる。単純な図形はSVG、絵としての質感が必要なら画像

```python
# 画像の軽量化（今回使った処理）
im = im.crop(bbox)                                    # 余白削除
im = im.resize((w, 300), Image.LANCZOS)               # リサイズ
im.quantize(colors=32, method=Image.FASTOCTREE)       # 減色
```

## 4. 状態管理・永続化

```js
// 必ず try-catch で包む。非対応環境でも壊れないこと
try{ localStorage.setItem('key', JSON.stringify(data)); }catch(e){}
```

- 状態は**単一のオブジェクトに集約**し、`render()` 一箇所で画面に反映する。DOM直接操作を散らかすと必ず表示がズレる
- `setInterval` によるバックグラウンド進行は、**非アクティブなモードでは必ず停止**する（`if(mode!=='main') return;`）
- 保存失敗＝リセットで済む設計にしておく。ローカルストレージを前提にしない

## 5. IP・素材のルール

- **公式キャラクター・ロゴは使用不可**。社内利用でもブランドチームの許諾が必要
- コーポレートカラーやトーンの流用は問題ない。**「らしさ」は配色とモチーフで表現する**
- 生成AIで作ったオリジナルイラストは安全。ただし既存キャラに酷似させない
- 差し替えを見越して、**キャラ描画は関数1つに隔離**しておく（`petHTML(kind)` の形）。公式素材の許諾が下りたら1箇所の変更で済む

## 6. デプロイ手順（GitHub Pages）

1. GitHub Desktop で新規リポジトリ作成（**README にチェック**）
2. ローカルフォルダに HTML を置き、**ファイル名を `index.html` にする**
3. Commit to main → **Push origin**（※ここを忘れやすい）
4. GitHub の Settings → Pages → Branch を `main` / `(root)` → Save
5. `https://<user>.github.io/<repo>/` が発行される
6. Meta AI アプリ → 開発者モード → Web App として URL 登録

**詰まりポイント：**

| 症状 | 原因 |
|---|---|
| README しか表示されない | `index.html` が push されていない |
| Pages に upgrade 表示 | リポジトリが Private |
| Branch に `main` が無い | push 未完了 |
| 404 | 反映待ち（1〜3分）またはファイル名違い |

**リポジトリは Public 必須**（無料プランの場合）。社外秘のロジックは載せない。

## 7. 開発フロー

```
① 仕様を6入力にマップできるか机上で確認
② PCブラウザで単一HTMLとして完成させる（ここに時間の9割）
③ 600×600 に縮めて崩れないか確認
④ GitHub Pages にデプロイ
⑤ 実機で確認 → 視認性・文字サイズのみ調整
```

- **②を飛ばして実機で試行錯誤しない。** 反映に毎回数分かかるため効率が壊滅的に落ちる
- ブラウザの開発者ツールで幅600pxに固定すれば、レイアウト検証はほぼ実機と一致する
- 実機でしか分からないのは**視認性・文字サイズ・ジェスチャーの体感**の3点だけ。それ以外はPCで潰す
