- **[v3.2] 地形レイヤ = 数値DEMの等高線(DATA_SOURCES 優先1のランタイム側)**: `hillshademap` の z13固定ラスタ反転を廃止し、
  地理院 標高タイル(`dem5a_png` z15 / `dem_png` 〜z14)をデコードして等高線を自前描画。
  タイル枚数が12枚に収まる最大ズームを自動選択、dem5a の欠損域が半数を超えたら dem_png(z14)へ自動フォールバック。
  等高線間隔は**画面上の線間隔**から決める(レンジだけだと急斜面で数px間隔に潰れて白い塊になる。勾配60%点で10px以上空くまで間隔を上げる)。
  地図は非活性色1色に統一し主曲線は太さで区別(明るい色はルートと現在地に取っておく)。スケールバー/N↑/クレジットの下は `clearRect` で消す。
  実タイルで確認済み: 高尾山=50m間隔、皇居ラン=5m間隔(旧実装ではほぼ無地だった堀と台地が出る)、富士山=100m間隔
- **[v3.2] gpx2route.py のDEM投入口(DATA_SOURCES 優先1のツール側)**: `--emit-dem-fetch` が標高タイルのDLスクリプトを出力し、
  手元で実行して `--dem-tiles dem/` で投入する(Overpassと同じオフライン2段構え)。PNGデコードは **stdlibのzlibだけ**で書いてある(Pillow不要)。
  投入すると (a) 峰の可視判定をレイキャストで自動化して `v:1` を立てる、(b) 標高欠損POIを埋める、(c) GPXのele信頼性を検査する。
  **レイキャストの設計上の勘所** — 低ズームDEMは尾根を平滑化して標高を過小評価し(z11実測: 高尾山599→591m、富士山3776→3761m)、
  これは「見える」側に偏るので危険。地形側は周囲1セルの最大(`elev_max`)で見る。
  視線に一律の余裕を持たせる方式は**不可**(観測点の足元では視線が必ず地面すれすれを通るので、実際に見える対象まで落ちる。実測で確認)。
  代わりに両端 `max(60m, 2セル)` 以内のサンプルを除外する。地球の丸み+大気差は等価半径7/6で補正。
  DEMが欠けた区間を含む視線は「不明」であって「見える」ではない → `v` は 0 のまま。
  実タイル(z11)で確認済み: 高尾山から 富士山・丹沢山・大山・大岳山・御岳山=可視 / 雲取山・箱根山=遮蔽

## 4. プラットフォーム既知事実(引き継ぎ必須・実機で確定済み)

**該当コードを触る前に必ず読む。** 体験設計書§10と同内容。

1. センサー権限は「履歴変更前」かつ「同一ジェスチャー内で同期発行」でないと`requestPermission`が永久pending
2. グラスの方位は`alpha`直がコンパス方位(iOSの`webkitCompassHeading`とは別・標準Androidの`360-α`とも別)。診断画面で`hmode`切替可能
3. 方位は起動後数秒デタラメ→円形EMA平滑+較正ゲート実装済み(`headingSettled`)
4. `watchPosition`は静止時に報告停止→20秒無報告でキープアライブ単発測位を実装済み
5. Notifications非対応→プル型設計(`visibilitychange`/`pageshow`)
6. バックはシェルが`history.back()`、pushState上限5段
7. オフライン起動にはSW必須、キャッシュファーストは更新不能になる→ネット優先+4秒フォールバック(sw.js実装済み)
