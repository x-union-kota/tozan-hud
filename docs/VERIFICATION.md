# VERIFICATION.md — 検証チェーン⑥⑦ 手順書

自動テスト(コア/スモーク/ツール)で押さえられない2つを、手で再現できる形にしたもの。

- **⑥ simで既知ゴーストとの相対値照合** — 背中(ゴースト)が出している位置が、解析的に分かる値と一致するか
- **⑦ Stellariumとの照合** — 天体の方位・高度が外部の天文ソフトと一致するか

①〜⑤は体験設計書側の定義で、このリポジトリには入っていない。ここでは扱わない。

どちらも画面は絵しか出さないので、突き合わせには数字が要る。そのために
`window.__THUD.dumpGhost()` / `dumpSky()` を用意してある(検証専用のフック)。

---

## 共通の準備

```bash
python3 tools/build.py
cd dist && python3 -m http.server 8777
```

ブラウザで `http://127.0.0.1:8777/index.html?sim=1` を開く。
開発者ツールのコンソールを出しておく。`?t=HH:MM` を足すと時刻を上書きできる(日付は今日のまま)。

sim専用キー: `s` 速度×5/20/60、`g` ゴール手前へ早送り、`d` 逸脱注入、`l` GPS喪失。

## ⑥ simで既知ゴーストとの相対値照合

### 何を確かめるのか

ゴーストソース4つのうち **目標ペース** と **標準CT** は、位置が閉じた式で決まる。

| ソース | 解析値 |
| --- | --- |
| `pace`(目標ペース) | `along = 全長 × 経過分 / 目標分`(周回は1周ごとに走り直すので経過はラップ経過) |
| `ct`(標準CT) | `along = CORE.ctInverse(route, 経過分)` |

`last`(前回の自分)と`lap1`(1周目の自分)は記録の再生なので解析値が無い。この2つは
スモークテストの回帰(記録→再生で同じ位置に戻る)に任せ、ここでは扱わない。

`dumpGhost()` は実際に描画に使っている `ghostAlongNow()` の値と、上の解析値を並べて返す。
**両者がズレたら、画面のゴーストは嘘をついている。**

### 手順

1. ルート選択で `→` を1回押して **高尾山 1号路 往復** を出し、`Enter` で ready へ
2. `↑` で目標ペース層を開き、`Enter` でそのまま確定(既定は標準CTと同じ値)
3. `Enter` で計測開始。10秒ほど待つ
4. コンソールで:

```js
__THUD.dumpGhost()
```

5. `ghostAlong` と `expectPace` が **一致**(丸め差の±1m以内)していることを確認する
6. 20秒ほど空けてもう一度実行し、両方が同じだけ増えていることを確認する

### 実測例(v3.2)

```
{ src: 'pace', paceGoal: 210, total: 5551, elapsedMin: 0.717,
  along: 18, ghostAlong: 19, expectPace: 19, gapM: -1 }
{ src: 'pace', paceGoal: 210, total: 5551, elapsedMin: 1.433,
  along: 37, ghostAlong: 38, expectPace: 38, gapM: -1 }
```

標準CTソースも同じ手順で確認する。コンソールから直接切り替えられる:

```js
__THUD.S.ghostSrc = 'ct'; __THUD.S.paceGoal = null; __THUD.dumpGhost()
```

```
{ src: 'ct', elapsedMin: 3.510, ghostAlong: 42, expectCt: 42 }
{ src: 'ct', elapsedMin: 4.217, ghostAlong: 50, expectCt: 50 }
```

### 合わないときに疑うところ

| 症状 | 疑うところ |
| --- | --- |
| `ghostAlong` が `null` | `S.tracking` が false / 目標ペース未設定で `src` が `pace` のまま |
| 周回で2周目に急に合わなくなる | `pace` は `lapStartMs` 基準。ラップ発火で基準が変わる仕様(バグではない) |
| `expectPace` が `null` | `paceGoal` が入っていない。ready の `↑` で設定したか |
| 一定のオフセットでズレ続ける | `S.startMs` と `nowMs()` の基準(`?t=` の時刻上書き)を確認 |

## ⑦ Stellariumとの照合

### 何を確かめるのか

`src/astro.js` が出す天体の **方位(az)・高度(alt)** が外部の天文ソフトと一致するか。
太陽は既知値と照合済み(core.test.js の日没テスト)だが、月・惑星・恒星は目視でしか
確かめていない。ここを数字で押さえる。

### 先に: Stellarium無しでできる一次チェック

座標変換(赤道座標→地平座標)だけなら、外部ソフト無しで厳密に確かめられる。
**ここが合わないなら暦の話をする前に変換がおかしい**ので、先にこれを通す。

```js
const S = __THUD.S, t = __THUD.nowMs(), la = S.lastFix.la, lo = S.lastFix.lo;
ASTRO.altAz(0, 90, la, lo, t)      // 天の北極(dec=+90)
```

| 確かめること | 期待 | 実測(v3.2・高尾山起点) |
| --- | --- | --- |
| 天の北極の高度 = 観測地の緯度 | 厳密に一致 | 高度 35.633° / 緯度 35.633° ✓ |
| 天の北極の方位 = 真北 | 0.000° | 0.000° ✓ |
| 北極星の高度 ≒ 緯度 | 緯度±0.74°(極からの離角) | 35.7°(方位 0.9°) ✓ |
| 夜間の太陽高度 | 負 | 22:00 で −39.5° ✓ |

この4つが通っていれば、残る差は暦(月・惑星の軌道計算)と歳差だけに絞れる。

### 手順

1. 計測を開始し、方位が収束するまで待つ(`S.headingSettled` が true)
   simでは方位が来ないので、コンソールで固定してよい:
   ```js
   __THUD.S.heading = 200; __THUD.S.headingReal = Date.now(); __THUD.S.headingSettled = true;
   ```
2. コンソールで:
   ```js
   copy(JSON.stringify(__THUD.dumpSky(), null, 1))     // copy() が無ければそのまま表示して手で写す
   ```
3. 出力の先頭に **時刻(`at`)・緯度経度(`lat`/`lon`)** が入っている。Stellarium 側を同じに設定する
   - 場所: `F6` → 緯度・経度を手入力(標高0)
   - 日時: `F5` → `at` に合わせる(タイムゾーンに注意。`at` はローカル時刻表記)
4. Stellarium の設定を2つ変える:
   - **大気(refraction)を切る** — `F4` → 空と表示環境 → 大気 のチェックを外す。
     入れたままだと低空で最大0.5°ずれ、実装の誤差と区別がつかない
   - 方位角の基準を **北=0°・東回り** にする(Stellariumの既定表示と合っているか確認する)
5. `objects` の各天体を Stellarium で検索(`F3`)し、方位角/高度を比べる

### 判定

| 対象 | 許容 | 理由 |
| --- | --- | --- |
| 太陽・月・惑星 | **±0.5°** | 平均軌道要素なので月は誤差が大きめ。0.5°(月の視直径)を超えたら実装を疑う |
| 恒星(高度20°以上) | **±1.0°** | 下記の既知の系統差を含む |
| 恒星(高度20°未満) | 参考値 | 大気を切っていても地平近くは誤差が乗る。判定に使わない |

### 既知の系統差(バグではない)

- **歳差を入れていない。** 星表はJ2000座標のまま。2026年なら約26年ぶんで **最大0.4°程度**
  の系統的なズレが出る。Stellariumは歳差を入れるので、この差は必ず出る。
  ラベル用途(どの星か分かればよい)には十分という判断。精度を上げるなら
  `astro.js` に歳差の回転を足す
- **固有運動を入れていない。** 影響はバーナード星など一部を除き無視できる
- **視差・光行差を入れていない。** 20秒角程度で、上の許容の内側

### 星の名前について

ラベルが出るのは1.3等より明るい20星。うち15星は和名(`make_stars.py` の上書き辞書)、
残る5星(Rigil Kentaurus / Achernar / Hadar / Acrux など)はHYGの英語名のまま出る。
いずれも**日本からは見えない南天の星**なので実用上あたらない。北半球以外で使うなら
`make_stars.py` の `STARS` テーブルに和名を足す。

### 合わないときに疑うところ

| 症状 | 疑うところ |
| --- | --- |
| 全天体が同じ角度だけ方位方向にズレる | `headingTrue()` の偏角。`dumpSky().dec` がルートの `dec` と一致しているか。実機なら `hmode`(α直/360−α) |
| 高度だけ合わない | 緯度の符号、`at` の時刻(UTC/ローカル)の取り違え |
| 恒星だけ0.3〜0.5°ズレる | 歳差(上記)。系統差なので全星で同じ向き・同じ量になる |
| 月だけ大きくズレる | `moonEcl` の主要項のみ実装。1°を超えるなら項の追加を検討 |

```bash

python3 tools/gpx2route.py --emit-wmm-fetch > fetch.sh && sh fetch.sh
python3 tools/gpx2route.py --wmm WMM2025COF.zip --wmm-test WMM_TEST_VALUES.txt
# → 12点 / 偏角の最大誤差 0.0046° / 成分 0.05nT で一致すること

# 星表: 星座線が参照するHIPが全て解決したかを make_stars.py が終了時に検査する

# → 「fabの参照HIPはすべて解決した(線は欠けない)」が出ること
```
